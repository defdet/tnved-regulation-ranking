# Тестовое задание: сопоставление таможенных деклараций с регуляциями ТН ВЭД ЕАЭС

Генерация предсказаний:

```bash
cd solution
pip install -r requirements.txt
python prepare_models.py                 # разовая загрузка весов; требует сети
python run.py --data ./data --out ./out  # использует GPU при наличии CUDA, иначе CPU
```

## Результаты

Замерено на 120 декларациях по самостоятельно построенной разметке
(`solution/docs/dev_labels.jsonl`; лейблы не были предоставлены).

| Метрика | Минимум | Только лексика | CPU | GPU (T4)|
|---|---|---|---|---|
| Hit@1 | 0,30 | 0,583 | **0,675** | **0,783** |
| Hit@5 | 0,68 | 0,967 | **0,975** | **0,992** |
| Hit@10 | 0,80 | 0,983 | **0,992** | **1,000** |
| MRR@10 | 0,45 | 0,739 | **0,798** | **0,873** |

GPU-конфигурация (Tesla T4): 993 секунды, пиковое использование VRAM 14,7 ГБ.
CPU-конфигурация: 158 секунд, пиковое использование RAM: 5,52 ГБ из 8.

`out/predictions.csv` в репозитории получен в GPU-конфигурации, которая выбирается
по умолчанию при наличии CUDA.

## Как работает

Три этапа: поиск по косинусной близости (TF-IDF по символьным n-граммам и
леммам, объединение через RRF) → переранжирование кросс-энкодером → проверка
числовых условий. Если декларация называет величину, а кандидат задаёт для неё
диапазон, кандидат получает небольшую надбавку за попадание и такой же штраф за
непопадание. Для разных этапов строятся три представления регуляции: многие из
360 кодов сгруппированы по три внутри товарной позиции, а их описания совпадают
почти полностью. Короткую различающую часть поэтому нужно выделять отдельно.
